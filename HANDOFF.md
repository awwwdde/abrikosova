# Точка входа для новой сессии

Дата последнего обновления: 31.08.2026. Обновляй этот файл в конце каждой сессии.

## Что это за проект

Переписывание сайта кондитерской `abrikosova-elena.ru` со старого Django на Next.js 15 + FastAPI.
Пишем **с нуля** — код старого сайта не переносится.

```
new/     готовое ТЗ: analysis/ANALYSIS.md + spec/00..06 + wireframes/skeleton/*.html
old/     старый Django-сайт — ТОЛЬКО референс (бизнес-логика, тексты, структура каталога)
app/     сам проект: монорепо apps/web + apps/api
```

**Порядок чтения перед работой:** `new/spec/00-overview.md` → `01-data-model.md` → `02-api-contract.md`
→ `03-pages-wireframes.md`. План работ — `new/spec/06-implementation-plan.md`, он же чек-лист этапов.

## Первые шаги новой сессии

```bash
cd app && docker compose up -d
```

- web — http://localhost:3000
- api — http://localhost:8001 (порт нестандартный, см. ниже), Swagger http://localhost:8001/docs

Контейнер `api` на старте сам накатывает миграции и сид.

Дальше — **Этап 2** по `new/spec/06-implementation-plan.md`: наполнить публичный API реальной логикой.
Порядок: каталог (список с фильтрами/сортировкой/пагинацией, карточка с похожими и начинками) →
галерея/отзывы/страницы → корзина на httpOnly cookie `cart_id` → заказы с пересчётом суммы на сервере →
заявки → e-mail-уведомления через `BackgroundTasks` → rate limiting. Pydantic-схем ещё нет, они пишутся
вместе с реализацией эндпоинтов.

## Особенности этой машины

- **Порты 5432 и 8000 заняты другим проектом** (`svidanie-db-1`, `svidanie-api-1`). Их не трогали.
  В `docker-compose.yml` порты хоста вынесены в переменные, локальный `app/.env` задаёт
  `POSTGRES_HOST_PORT=5433`, `API_HOST_PORT=8001`. `app/.env.example` описывает эти переменные.
  Дефолты в коде остались каноничными (5432/8000) — на чистой машине всё поднимется без правок.
- `apps/api/.env` указывает на `localhost:5433` — это для запуска API вне докера (venv в `apps/api/.venv`).
- Docker Desktop на старте сессии был выключен; если команды `docker` падают на pipe — запустить его.

## Решения, уже принятые (не пересматривать без причины)

- **Хостинг** — Timeweb Cloud: App Platform, Managed PostgreSQL, Managed Redis, S3 Object Storage.
  Build context на App Platform — `app/apps/web` и `app/apps/api`.
- **Корзина** — один источник правды на бэкенде, httpOnly cookie `cart_id`, без localStorage.
- **Фоновые задачи** — `BackgroundTasks` для e-mail, APScheduler для бэкапов. Redis — только кэш и rate-limit.
- **Админка** — route-группа `/admin` внутри того же Next.js-приложения.
- **UI-библиотека** — shadcn/ui, как зафиксировано в договоре. (В одной из сессий её убирали и вернули
  обратно по решению заказчика — не убирать снова без прямого указания.)
- **Дизайна пока нет** — нейтральная тема, макеты придут отдельно и не меняют структуру, API и модель данных.
- **Контент старого сайта не мигрируется** — только seed-данные.

## Расхождения с ТЗ, которые стоит внести в спеку

1. **Корзина отсутствует в модели данных.** `01-data-model.md` перечисляет 14 сущностей, среди них нет
   `Cart`/`CartItem`, хотя серверная корзина требуется `02-api-contract.md`. Реализованы в
   `apps/api/app/models/cart.py` (`Cart.id` — UUID, уходит в cookie; уникальность пары cart+product).
   Модель данных стоит дополнить этими двумя таблицами.
2. **Поля изображений названы `*_key`, а не `image_url`.** В спеке `image_url`, но хранится ключ объекта
   в S3, а публичный URL собирается на выдаче — держать в БД полный URL значит зашить в данные адрес
   бакета. В коде: `ProductImage.storage_key`, `CustomCake.image_key`, `Filling.image_key`,
   `GalleryItem.image_key`, `Review.image_key`, `ConsultationRequest.reference_image_key`.
3. `new/spec/03-pages-wireframes.md:132` — в пункте «Форма обратной связи» осталась старая ремарка
   «Договор не выделяет отдельный эндпоинт... см. примечание ниже», хотя `POST /contacts/feedback`
   уже описан в `02-api-contract.md:36`. Заменить на `API: POST /contacts/feedback`.

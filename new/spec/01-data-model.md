# Модель данных (SQLAlchemy 2 / PostgreSQL)

> **Редакция 2 (25.09.2026).** Модель дополнена решениями из PDF «Этап 1 · Аналитика и проектирование»: каталог из 5 групп со сквозными фильтрами (повод, ограничения в питании, срок, порции, цена), обязательные поля карточки (вес и порции числами, КБЖУ, перевозка, срок изготовления), отзывы к товару, подписи работ в галерее, поля заявки на торт и интервал доставки. Изменения помечены 🆕². Реализация — миграция `7c1e2a9d4f10` в `app/apps/api/alembic/versions/`.
>
> **Именование полей изображений.** Там, где ниже написано `image_url`, в коде поле называется `image_key` / `storage_key`: в БД хранится ключ объекта в S3, а публичный URL собирается на выдаче. Так смена домена хранилища не требует миграции данных.

Основа взята из текущей Django-модели (см. `ANALYSIS.md`, раздел 3), расширена недостающими по договору полями и сущностями (раздел 4.2, 4.6, 4.7 Приложения №1). Ниже — сущности, поля, типы и связи. Точные имена классов/таблиц Claude Code может адаптировать под конвенции проекта, но набор полей и связей — обязателен.

Во всех таблицах ниже колонка **«Обязательное»** отвечает строго на вопрос «должно ли поле быть заполнено» (✅ = `NOT NULL`/обязательно к вводу, пусто = `nullable`/опционально) и никогда не используется для отметки «это новое поле» — для этого есть отдельная колонка **«Комментарий»**, где новые относительно старой Django-модели поля помечены значком 🆕.

## Список сущностей

1. Category — категория каталога
2. SubCategory — подкатегория
3. Product — товар
4. ProductImage — фото товара (до 6 шт.)
5. ProductTag — метка товара (новинка/хит/сезон) — enum, не отдельная таблица
6. CustomCake — позиция «Торты на заказ» (карточка с ценой «от»)
7. Filling — начинка (для тортов на заказ и для карточки торта в каталоге)
8. GalleryItem — «Примеры работ» (фото + подпись, без цены)
9. Review — отзыв
10. ConsultationRequest — заявка на консультацию/обратную связь
11. Order / OrderItem — заказ и позиции заказа
12. AdminUser — пользователь админ-панели
13. PageContent — редактируемый контент статичных страниц (главная/о нас/торты на заказ/контакты)
14. BackupRecord — метаданные резервных копий
15. Cart / CartItem — гостевая корзина (🆕² внесено в спеку по факту реализации: корзина живёт на сервере, см. `02-api-contract.md`)
16. AuditLogEntry — журнал действий администраторов (🆕² реализовано, в первой редакции значилось как «в идеале»)

### Перечисления 🆕²

| Enum | Значения | Где используется |
|---|---|---|
| `Occasion` (повод) | `birthday` День рождения, `kids` Детский, `wedding` Свадьба, `corporate` Корпоратив, `tea` К чаю | `Product.occasions[]`, `GalleryItem.occasion`, `ConsultationRequest.occasion` |
| `DietaryTag` (ограничения) | `gluten_free` Без глютена, `lactose_free` Без лактозы, `low_sugar` Сниженный сахар | `Product.dietary[]` |
| `PortionsRange` (фильтр) | `up_to_4` до 4, `4_8` 4–8, `8_15` 8–15, `over_15` больше 15 | только параметр фильтра, в БД не хранится |
| `Availability` (фильтр «Срок») | `today` в наличии сегодня, `preorder` на заказ | только параметр фильтра, вычисляется из `Product.lead_time_days` |
| `DeliveryInterval` | `09-12`, `12-15`, `15-18`, `18-21` | `Order.delivery_interval` |

Русские подписи значений отдаёт бэкенд (`GET /catalog/filters`), чтобы сайт и админка не держали каждый свою копию перевода.

Индексы: `(is_active, is_available)`, `(category_id, subcategory_id)`, `slug` unique — как в текущей модели; 🆕² GIN-индексы на `occasions` и `dietary` под фильтры по массивам.

## 12. PageContent (редактируемый контент статичных страниц)

Обобщение старых `AboutPageContent`/`ContactPageContent`/`CustomCakePageContent` в одну расширяемую модель по ключу страницы + JSON-блоки — это удобнее для админки, чем отдельная таблица на каждую страницу, и легко расширяется на новые блоки без миграции схемы:

| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| id | PK | ✅ | |
| page_key | enum[`home`,`about`,`custom_cakes`,`contacts`], unique | ✅ | |
| content | JSONB | ✅ | структура блоков, специфичная для страницы (см. `03-pages-wireframes.md` — набор полей = набор блоков на вайрфрейме страницы) |
| updated_at | timestamptz | ✅ | |

Для страницы `contacts` дополнительно хранятся структурированные поля отдельно от `content` (а не только внутри JSON), так как они используются в JSON-LD и футере: `address`, `phone`, `work_hours_weekdays`, `work_hours_weekend`, `delivery_hours`, `map_embed_code`.

🆕² К ним добавлены поля шапки сайта: `yandex_rating` (Numeric(2,1), 0…5), `yandex_reviews_count` (int), `yandex_maps_url` и `telegram_url` (только `https://` — ссылки попадают в `href` на каждой странице, `javascript:` там был бы XSS). Рейтинг вводится вручную: официального API рейтинга у Яндекса нет.

## Seed-данные для разработки

По решению, принятому в этой задаче, **контент из старой SQLite не переносится** — новая база наполняется реальным контентом заново через новую админку после сдачи. Для локальной разработки и демонстрации Claude Code должен создать seed-скрипт (`apps/api/app/seed.py` или Alembic data-migration), наполняющий БД **условными демо-данными**, а не реальными фото/текстами клиента:

- 🆕² 5 групп каталога из PDF «Этап 1» (раздел 12): **Торты** (бенто, детские, свадебные, классические, муссовые, фирменные — у всех `applies_fillings=true`), **Десерты и пирожные** (современные, классика, корпусные, трайфлы, чизкейки), **Печенье и конфеты** (овсяное, миндальное, cookies, трюфели, плитки), **Пироги и рулеты** (пироги, рулеты), **Наборы и подарки** (ассорти, наборы конфет, сертификат);
- ~20 товаров с плейсхолдер-изображениями, заполненными весом, порциями, сроком изготовления, поводами и ограничениями так, чтобы каждая комбинация фильтров что-то возвращала;
- 3–5 позиций «Торты на заказ», 4–6 начинок;
- 6–8 позиций «Примеры работ»;
- 4–6 отзывов;
- 1 учётная запись администратора (`owner`) с паролем из `.env`, не захардкоженным в коде.

Это нужно, чтобы фронтенд и API можно было полноценно тестировать без ожидания реального контента от клиента.

# Модель данных (SQLAlchemy 2 / PostgreSQL)

Основа взята из текущей Django-модели (см. `ANALYSIS.md`, раздел 3), расширена недостающими по договору полями и сущностями (раздел 4.2, 4.6, 4.7 Приложения №1). Ниже — сущности, поля, типы и связи. Точные имена классов/таблиц Claude Code может адаптировать под конвенции проекта, но набор полей и связей — обязателен.

Во всех таблицах ниже колонка **«Обязательное»** отвечает строго на вопрос «должно ли поле быть заполнено» (✅ = `NOT NULL`/обязательно к вводу, пусто = `nullable`/опционально) и никогда не используется для отметки «это новое поле» — для этого есть отдельная колонка **«Комментарий»**, где новые относительно старой Django-модели поля помечены значком 🆕.

## Список сущностей

1. Category — категория каталога
2. SubCategory — подкатегория
3. Product — товар
4. ProductImage — фото товара (до 6 шт.)
5. ProductTag — метка товара (новинка/хит/сезон) — enum, не отдельная таблица
6. CustomCake — позиция «Торты на заказ» (карточка с ценой «от»)
7. Filling — начинка (для тортов на заказ и для карточки торта в каталоге)
8. GalleryItem — «Примеры работ» (фото + подпись, без цены)
9. Review — отзыв
10. ConsultationRequest — заявка на консультацию/обратную связь
11. Order / OrderItem — заказ и позиции заказа
12. AdminUser — пользователь админ-панели
13. PageContent — редактируемый контент статичных страниц (главная/о нас/торты на заказ/контакты)
14. BackupRecord — метаданные резервных копий

## Seed-данные для разработки

По решению, принятому в этой задаче, **контент из старой SQLite не переносится** — новая база наполняется реальным контентом заново через новую админку после сдачи. Для локальной разработки и демонстрации Claude Code должен создать seed-скрипт (`apps/api/app/seed.py` или Alembic data-migration), наполняющий БД **условными демо-данными**, а не реальными фото/текстами клиента:

- 3–4 категории (например: «Торты», «Десерты», «Капкейки», «Сезонное») с 2–3 подкатегориями каждая (у подкатегорий типа «Торты» — `applies_fillings=true`) — финальный перечень категорий согласуется с заказчиком отдельно (раздел 4.1 договора), в seed используем как рабочую заглушку;
- 15–20 товаров с плейсхолдер-изображениями (можно использовать нейтральные заглушки-иконки вместо реальных фото — реальные фото передаст заказчик);
- 3–5 позиций «Торты на заказ», 4–6 начинок;
- 6–8 позиций «Примеры работ»;
- 4–6 отзывов;
- 1 учётная запись администратора (`owner`) с паролем из `.env`, не захардкоженным в коде.

Это нужно, чтобы фронтенд и API можно было полноценно тестировать без ожидания реального контента от клиента.

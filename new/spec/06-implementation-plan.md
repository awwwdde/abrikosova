# Пошаговый план реализации для Claude Code

Порядок задач построен так, чтобы на каждом шаге было что-то проверяемое (запускается, тестируется), а не «сначала весь бэкенд, потом весь фронт без возможности что-то посмотреть». Каждый этап — примерный набор задач для одной сессии Claude Code, не жёсткий тайминг.

## Этап 0. Инициализация репозитория

- [ ] Создать монорепо по структуре из `00-overview.md` (`apps/web`, `apps/api`, `docker-compose.yml`).
- [ ] `docker-compose.yml`: сервисы `postgres`, `redis`, `api` (FastAPI + uvicorn/hypercorn с hot-reload), `web` (Next.js dev) — только для локальной разработки.
- [ ] `Dockerfile` в `apps/web` и `apps/api` (продовые многостадийные сборки) — используются при деплое на Timeweb Cloud App Platform (см. Этап 9), поэтому сразу пишутся с расчётом на прод, а не только на локальный docker-compose.
- [ ] `.env.example` для обоих приложений (без реальных значений) + `.gitignore` с `.env`, `node_modules`, `__pycache__`, `.venv` и т.д. — этот пункт первым, чтобы повторить утечку кредов из старого проекта было невозможно физически.
- [ ] Базовая настройка линтеров/форматтеров: ESLint + Prettier для `web`, Ruff + Black (или единый Ruff) для `api`.

## Этап 1. Backend — фундамент

- [ ] SQLAlchemy 2 (async) модели по `01-data-model.md`.
- [ ] Alembic — инициализация, первая миграция со всеми таблицами.
- [ ] Pydantic-схемы (request/response) по доменам.
- [ ] Роутеры-заглушки для всех доменов из `02-api-contract.md` (пустая реализация, чтобы зафиксировать контракт путей).
- [ ] Seed-скрипт с демо-данными (см. `01-data-model.md`, раздел Seed-данные).
- [ ] `docker-compose up` поднимает БД + применяет миграции + сидирует данные — воспроизводимое окружение с первого дня.

## Этап 2. Backend — публичный API

- [ ] Каталог: категории, товары (список с фильтрами/сортировкой/пагинацией), карточка товара с похожими и начинками.
- [ ] Торты на заказ, галерея, отзывы, статичный контент страниц — GET-эндпоинты.
- [ ] Корзина — гостевая, на httpOnly cookie `cart_id`.
- [ ] Заказы — создание с валидацией условных полей (адрес при доставке), пересчёт суммы на сервере (не доверяем сумме от клиента).
- [ ] Заявка на консультацию / форма обратной связи.
- [ ] E-mail-уведомление администратору при новом заказе/заявке — через `FastAPI BackgroundTasks` в процессе `apps/api`, без отдельного воркера и без Redis-очереди (решение зафиксировано в `00-overview.md`, раздел «Инфраструктура», примечание про фоновые задачи; Redis в проекте используется только как кэш и для rate limiting).
- [ ] Rate limiting на мутирующих публичных эндпоинтах.

## Этап 3. Backend — auth и admin API

- [ ] JWT-аутентификация (access + refresh), эндпоинты `/auth/*`.
- [ ] Admin CRUD по всем доменам из `02-api-contract.md` с проверкой роли.
- [ ] Загрузка изображений (товары, галерея, начинки, торты на заказ) с конвертацией в WEBP и лимитом 6 фото на товар.
- [ ] Резервное копирование — фоновая задача (pg_dump или аналог) + ручной запуск из admin API.

## Этап 4. Frontend — фундамент

- [ ] Next.js 15 App Router, TypeScript strict, Tailwind 4, shadcn/ui — базовая настройка темы (нейтральная, без финальных цветов — они придут от дизайнера).
- [ ] Слой API-клиента (типизированные функции поверх `fetch`, ключи React Query/SWR по доменам).
- [ ] Общие компоненты: `Header`, `MobileMenu`, `Footer`, `CartIcon`, `FloatingSocialWidget` — по `03-pages-wireframes.md`, раздел «Общие блоки».
- [ ] React Hook Form + Zod — общий паттерн формы (переиспользуемые хуки/компоненты полей), чтобы не дублировать между 4 формами сайта (консультация, контакты, чекаут, отзыв в админке).

## Этап 5. Frontend — публичные страницы (без дизайна, по вайрфреймам)

Реализовать в порядке приоритета для сквозной проверки пути «увидел товар → купил»:

1. Каталог + карточка товара + корзина + чекаут + страница подтверждения (основной денежный путь).
2. Главная.
3. Торты на заказ (с формой консультации).
4. О нас, Примеры работ, Контакты (с формой обратной связи).
5. Служебные страницы (404, Политика конфиденциальности, Пользовательское соглашение).

Каждая страница на этом этапе должна в точности следовать блок-схеме из `03-pages-wireframes.md` и HTML-скелету из `wireframes/skeleton/` — верстается **без** финальных цветов/шрифтов (нейтральная Tailwind-тема), стилизация подключается отдельным этапом после получения дизайна от дизайнера.

## Этап 6. Frontend — admin-панель

- [ ] Middleware защиты `/admin/**` + страница логина.
- [ ] Разделы по `04-admin-panel.md` в порядке: Каталог → Заказы → Заявки → Отзывы/Галерея → Контент страниц → Пользователи/Бэкапы.

## Этап 7. Интеграции и нефункциональные требования

- [ ] Карта на странице контактов, аналитика (Метрика/GA), `sitemap.ts`/`robots.ts`, JSON-LD.
- [ ] Проверка требований безопасности из `05-nonfunctional-and-acceptance.md` (HTTPS/секреты/rate-limit/CSRF) — как отдельный чек-лист перед сдачей, а не «между делом».

## Этап 8. Тестирование и подготовка к сдаче

- [ ] Backend: unit-тесты бизнес-логики (расчёт суммы заказа, валидация условных полей), интеграционные тесты ключевых эндпоинтов.
- [ ] Frontend: хотя бы smoke-тесты основного пути (Playwright: добавить в корзину → оформить заказ) — учитывая, что в старом проекте автотестов не было вовсе.
- [ ] Прогон по критериям приёмки из `05-nonfunctional-and-acceptance.md`.

## Этап 9. Деплой на Timeweb Cloud

Хостинг зафиксирован — Timeweb Cloud (см. `00-overview.md`, раздел «Инфраструктура»). Порядок настройки:

- [ ] Завести Managed PostgreSQL и Managed Redis в личном кабинете Timeweb Cloud, получить строки подключения.
- [ ] Завести бакет S3 Object Storage для изображений и файлов бэкапов, получить ключи доступа.
- [ ] Подключить репозиторий к [App Platform](https://timeweb.cloud/docs/apps): два приложения — `apps/web` (Next.js) и `apps/api` (FastAPI), у каждого свой Dockerfile (добавить на этапе 0, если ещё не добавлен) или сборка через buildpack — проверить на этапе 0, какой вариант проще для конкретных версий Next.js 15/FastAPI на момент реализации.
- [ ] Прописать переменные окружения обоих приложений в панели Timeweb Cloud (не в репозитории) — строки подключения к Postgres/Redis, ключи S3, `JWT_SECRET`, SMTP-креды, ID счётчиков аналитики.
- [ ] Подключить домен `abrikosova-elena.ru` (или новый, если решите сменить) к приложению `apps/web`, проверить автовыпуск HTTPS-сертификата.
- [ ] Прогнать миграции Alembic на проде (разово, из CI-шага деплоя или вручную при первом релизе), запустить сид ролей администратора (не тестовых демо-данных — на проде сид только пользователь `owner`, каталог наполняется вручную через админку).
- [ ] Включить автоматические снапшоты на Managed PostgreSQL, проверить, что плановый `pg_dump`-бэкап из админки действительно кладёт файл в S3-бакет.
- [ ] Финальный прогон Lighthouse на проде и полный чек-лист критериев приёмки против боевого URL, а не только локального окружения.

## Важное примечание про дизайн

Этот план описывает верстку и логику **без визуального дизайна** — все страницы на этапах 5–6 используют нейтральную нерасцвеченную Tailwind-тему и структуру строго по вайрфреймам. Как только дизайнер передаёт готовые макеты (Figma), это отдельная последующая задача — «применить дизайн-систему» (цвета, типографика, отступы, финальные иконки, анимации по духу макета через Motion/GSAP), которая **не меняет** структуру, API-контракт или модель данных, зафиксированные в этом ТЗ.

# Спецификация админ-панели (`/admin`)

Требования — из раздела 5 Приложения №1 к договору («Понятный интерфейс управления содержимым сайта без навыков программирования»). Технически — route-группа `app/admin/**` внутри Next.js-приложения, защищённая middleware, который проверяет JWT (см. `02-api-contract.md`, домен Auth) и роль пользователя.

## Вход и защита

- Страница `/admin/login` — форма email + пароль → `POST /auth/login`.
- Middleware Next.js на всех маршрутах `/admin/**` (кроме `/admin/login`) проверяет наличие валидного access-токена (в httpOnly cookie или в памяти + silent refresh через `/auth/refresh`); при отсутствии — редирект на `/admin/login`.
- Хардкод логина/пароля в коде или в seed-данных без возможности смены — недопустим: пароль администратора задаётся через `.env` только для сид-пользователя при первом деплое, дальше меняется из самой админки.

## Структура разделов (левое меню админки)

1. **Дашборд** (`/admin`) — сводка: количество новых заказов, новых заявок на консультацию за сегодня/неделю, быстрые ссылки. Не заявлено отдельно в договоре, но упрощает ежедневную работу владелицы бизнеса — минимальная реализация (несколько счётчиков), не должна становиться отдельным большим модулем аналитики.
2. **Каталог** (`/admin/catalog`)
   - Список категорий/подкатегорий — создание, редактирование, изменение порядка (drag-and-drop или поле `order`), скрытие (`is_active`).
   - Список товаров — таблица с поиском/фильтром по категории и наличию, массовое скрытие.
   - Карточка товара — форма со всеми полями из `01-data-model.md` (включая новые: порции, срок годности, условия хранения, метки), блок загрузки до 6 изображений с drag-and-drop сортировкой и выбором главного фото, предпросмотр.
3. **Торты на заказ** (`/admin/custom-cakes`) — CRUD позиций и начинок.
4. **Примеры работ** (`/admin/gallery`) — CRUD, загрузка фото + подпись.
5. **Отзывы** (`/admin/reviews`) — список всех отзывов (включая неопубликованные), переключатель публикации, редактирование текста, удаление.
6. **Заказы** (`/admin/orders`) — список с фильтром по статусу/дате, карточка заказа (состав, контакты клиента, способ получения, адрес/дата если есть) со сменой статуса.
7. **Заявки на консультацию** (`/admin/consultations`) — аналогично заказам, но для `ConsultationRequest` (включая заявки с формы контактов, см. примечание в `03-pages-wireframes.md`).
8. **Контент страниц** (`/admin/pages`) — редактор блоков для «Главная», «О нас», «Торты на заказ», «Контакты» (форма, поля которой соответствуют структуре `content` JSONB из `01-data-model.md` и блокам вайрфрейма соответствующей страницы).
9. **Пользователи** (`/admin/users`, только `owner`) — список администраторов, приглашение нового, смена роли, деактивация.
10. **Резервные копии** (`/admin/backups`, только `owner`) — список бэкапов (дата, размер, статус), кнопка «Создать резервную копию сейчас», кнопка восстановления из выбранной копии (с явным предупреждением/подтверждением — необратимое действие).

## Общие требования к UI админки

- shadcn/ui как основа компонентов (таблицы, формы, модалки, toast-уведомления об успехе/ошибке операций).
- Любое разрушительное действие (удаление товара, восстановление бэкапа) — через подтверждающую модалку.
- Формы редактирования — та же связка React Hook Form + Zod, что и на публичной части сайта, чтобы не плодить два разных подхода к валидации в одном проекте.
- Пагинация и поиск во всех списочных разделах (заказы, товары, отзывы и т.д.) — без этого админка станет неюзабельной уже при первых 50+ товарах.

# Вайрфреймы страниц (структура, без визуального дизайна)

> **Редакция 2 (25.09.2026).** Дополнено по PDF «Этап 1 · Аналитика и проектирование» (карта сайта, логика каталога, сценарии заказа, карточка товара). Главная мысль документа: сайт обслуживает два ритма — «позиция в наличии» (минуты: в корзину → оформил) и «торт на заказ» (недели: заявка → согласование → получил в дату), и развилка ставится на входе. Изменения помечены 🆕². Визуальный язык (мудборд, блок 2) — отдельный документ и на структуру не влияет.

Формат каждой страницы: назначение → порядок блоков mobile (приоритетное устройство по договору) → отличия desktop → состояния (пусто/загрузка/ошибка) → источник данных → примечания по анимациям. Цвета, шрифты, отступы, иконография — вне этого документа, это зона ответственности дизайнера (Figma) и Tailwind-темы, настраиваемой позже.

Условные обозначения: `[Блок]` — секция страницы, `→` — переход/ссылка, `API:` — какой эндпоинт из `02-api-contract.md` наполняет блок.

## 1. Главная (`/`)

**Назначение:** первый экран должен за 3 секунды объяснить, что это кондитерская ручной работы, вызвать доверие и сразу дать путь в каталог.

**Mobile, порядок блоков сверху вниз:**

1. `[Header]` — липкая шапка: лого (компактный, круглый вариант) слева, бургер-меню и иконка корзины (с бейджем количества) справа.
2. `[Hero]` — полноэкранный (≈80–90vh) блок: фоновое изображение/видео продукции, короткий заголовок-посыл, подзаголовок, CTA-кнопка «Смотреть каталог» → `/catalog`.
3. `[Популярные позиции]` — горизонтальный скролл-ряд карточек товара (фото, название, цена, кнопка «В корзину»). `API: GET /catalog/products?is_featured=true`. Заголовок секции + ссылка «Весь каталог →».
4. `[Преимущества]` — 3–4 плитки с коротким текстом (например: «Натуральные ингредиенты», «Ручная работа», «Доставка по Москве», «Индивидуальный дизайн») — контент из `PageContent[home]`.
5. `[О личности бренда]` — фото кондитера + короткий текст-представление, CTA «Узнать больше» → `/about`.
6. `[Торты на заказ — тизер]` — горизонтальная галерея примеров (переиспользует часть данных `GET /custom-cakes` или `GET /gallery`), CTA «Обсудить свой торт» → `/custom-cakes`.
7. `[Отзывы]` — карусель из 3–5 отзывов (автор, текст, опционально фото/оценка). `API: GET /reviews?page_size=5`. Ссылка «Все отзывы →», если решите вынести отзывы на отдельную страницу (см. примечание ниже).
8. `[Повторный CTA]` — крупный блок «Готовы сделать заказ?» с кнопкой в каталог — перед футером, чтобы не терять конверсию у пользователей, доскроливших до конца.
9. `[Footer]` — см. общий блок «Футер» в конце документа.
10. Плавающий виджет соцсетей/чат (см. общий блок «Floating-виджет»).

🆕² **Уточнения по PDF «Этап 1» (приоритетнее списка выше, где расходятся):**

- **Первый экран решает за пять секунд**: продукт, цена и лицо бренда видны сразу. В hero — **развилка на входе** двумя кнопками: «Смотреть витрину» → `/catalog` (ритм «в наличии») и «Заказать торт» → `/custom-cakes` (ритм «под событие»). Тексты — `PageContent[home].content.hero`.
- `[Преимущества]` не строятся на «натуральных ингредиентах» и «ручной работе» — это входной билет, их пишут все конкуренты. Вместо них — три опоры бренда: мастер, вкус со своим почерком, заказ под событие.
- 🆕² `[Авторские начинки]` — выводятся на главную (раньше лежали на четвёртом пункте меню): `GET /custom-cakes` → `fillings[]`, CTA → `/custom-cakes`.
- 🆕² `[Цитата Елены]` — реплика от первого лица с подписью (`content.author`); о вкусе и работе говорит Елена, о сроках и доставке — кондитерская.
- 🆕² `[Кофейня на Гжатской]` — блок с адресом и часами (`content.coffee_shop` + структурированные поля `contacts`). Отдельной страницы кофейня не получает.
- `[Примеры работ]` вместо тизера тортов: работы с подписями (`GET /gallery?page_size=6`), CTA «Все работы» → `/gallery`.

**Desktop:** hero делится на две колонки (текст слева, изображение справа — этим управляет дизайнер), «Преимущества» — сетка 4 колонки вместо вертикального стека, «Популярные позиции» и «Отзывы» — те же горизонтальные ряды, но видно больше карточек одновременно, шапка разворачивается в горизонтальное меню без бургера.

**Примечание про «Отзывы»:** договор допускает вариант «блок на главной **и/или** на отдельной странице» (раздел 4.7). В этом ТЗ выбран вариант «блок на главной, без отдельной страницы отзывов» — это упрощает 9-страничную структуру без потери требования. Если заказчик после демонстрации попросит отдельную страницу — это готовая карточка `Review`+ эндпоинт `GET /reviews`, добавляется без изменения модели данных.

**Состояния:** если `is_featured` товаров нет (пустая база) — блок «Популярные позиции» скрывается целиком, не показывая пустой скелетон на проде. Если `GET /reviews` вернул пусто — блок «Отзывы» скрывается. Ошибка загрузки любого блока не должна ломать всю страницу (изоляция ошибок по секциям — важно при SSR/ISR).

**Анимации:** Motion — плавное появление секций при скролле (`fade + translateY`, единая длительность для всех секций страницы), hover-эффекты карточек. GSAP — если дизайнер заложит сложный параллакс/скролл-триггер в hero (решается на этапе вёрстки по готовому дизайну, здесь не фиксируем деталей).

## 2. Каталог (`/catalog`, `/catalog/[category]`, `/catalog/[category]/[subcategory]`)

**Назначение:** дать быстро найти нужный товар — по категории, по поиску, с сортировкой.

**Mobile:**

1. `[Header]` (общий).
2. `[Заголовок страницы + хлебные крошки]` — «Главная › Каталог» или «Главная › Каталог › Торты» при заходе в категорию (в старом коде хлебные крошки были только на странице товара — здесь они обязательны и в каталоге, см. `ANALYSIS.md` п. 2.2.6).
3. `[Поисковая строка]` — 🆕 отсутствовала в старой версии, обязательна по разделу 4.3 договора. Debounce-поиск по названию, обновляет список без перезагрузки страницы.
4. `[Кнопка «Категории»]` — открывает мобильную панель/шторку с деревом категорий (аналог текущей реализации, но без дублирования JS-логики между страницами — единый компонент).
5. `[Панель сортировки]` — select: «по цене ↑/↓», «по названию», «сначала новые» (`sort=price_asc|price_desc|name|new`) — отсутствовала в старом коде (`ANALYSIS.md`, п. 2.2.5).
5a. 🆕² `[Сквозные фильтры]` — чипы: **повод** (день рождения, детский, свадьба, корпоратив, к чаю), **ограничения** (без глютена, без лактозы, сниженный сахар), **срок** (в наличии сегодня / на заказ), **порции** (до 4, 4–8, 8–15, больше 15), **цена** (от–до). Значения и подписи — `API: GET /catalog/filters`. Выбранные фильтры живут в query-строке URL, чтобы подборку можно было отправить ссылкой («каталог с фильтром „детский“ и по порциям» — путь Марины). На мобильном — шторка «Фильтры» с кнопкой «Показать N позиций».
6. `[Сетка товаров]` — карточки в 2 колонки на мобильном (фото, метка если есть — «новинка/хит/сезон», название, 🆕² состав строкой, «1200 г · 10–12 порций», метки ограничений и «на заказ» при `lead_time_days > 0`, цена, кнопка «В корзину»). `API: GET /catalog/products`.
7. `[Пагинация / «Показать ещё»]` — 🆕 обязательна (в старом коде список жёстко обрезался 12 позициями без возможности увидеть остальное — `ANALYSIS.md`, п. 2.1.8).
8. `[Footer]`.

**Desktop:** сайдбар с деревом категорий постоянно виден слева (не шторка), сетка товаров — 3–4 колонки справа, поиск и сортировка в одной строке над сеткой.

**Состояния:** пустая категория → блок-заглушка «В этой категории пока нет товаров» с CTA «Смотреть весь каталог»; поиск без результатов → «Ничего не найдено по запросу "…"» + предложение сбросить фильтры; загрузка следующей страницы — skeleton-карточки вместо спиннера на весь экран.

## 3. Карточка товара (`/product/[slug]`)

🆕² Порядок блоков задан путём покупателя: аппетит → ответ про размер → снятие сомнений (PDF «Этап 1», раздел 14). Провал на пути Марины приходится на «Сомнение» — вес, порции, состав и отзывы должны стоять выше сгиба.

**Mobile:**

1. `[Header]`, `[Хлебные крошки]` — «Главная › Каталог › {Категория} › {Подкатегория} › {Товар}» (сохраняем логику из старого кода — она была реализована корректно).
2. `[Блок 01 · Галерея]` — до 6 кадров: десерт целиком, срез с начинкой, в упаковке, рядом с предметом для масштаба. Свайп/точки-индикатор, главное фото — `is_main`.
3. `[Блок 02 · Название, цена, размер]` — название, метки (новинка/хит/сезон); **цена, вес и порции тремя равными плашками** («480 ₽ · 100 г · 1 человек»); индикатор наличия; при `lead_time_days > 0` — «Готовим за N дня». Кнопки «В корзину» (с состоянием «В корзине ✓ / Перейти в корзину») и 🆕² вторичная «Спросить в Telegram» (`PageContent[contacts].telegram_url`). Кнопка заказа блокируется при `is_available=false`.
4. `[Блок 03 · Состав и метки]` — состав строкой, КБЖУ на 100 г раскрывающейся таблицей (если `nutrition != null`), метки ограничений (`dietary[]`).
5. `[Блок 04 · Хранение и срок]` — три плашки: срок годности, хранение, перевозка (`transport_time`).
6. `[Блок 05 · Доставка и оплата]` — доставка, самовывоз, оплата. Данные не дублируются в товаре — берутся из `PageContent[contacts].content` (`delivery`, `pickup`, `payment`).
7. `[Описание]` — полный текст.
8. `[Блок 06 · Отзывы и похожие]` — 🆕² отзывы о позиции (`reviews[]`, «Все отзывы (N)» → `GET /reviews?product={slug}`), ниже до 4 похожих из той же подкатегории. `API`: приходит вместе с ответом `GET /catalog/products/{slug}`.
9. `[Footer]`.

**Desktop:** галерея слева (главное фото крупно + миниатюры столбиком/рядом), блок цены/характеристик/кнопки справа — двухколоночная раскладка, остальное как на mobile.

**Состояния:** товар не найден → страница 404 (см. служебные страницы); товар есть, но `is_available=false` — кнопка заказа неактивна с поясняющим текстом «Сейчас недоступно, уточните в WhatsApp/телефону».

## 4. Торты на заказ (`/custom-cakes`)

**Mobile:**

1. `[Header]`, `[Hero страницы]` — заголовок + подзаголовок из `PageContent[custom_cakes]`.
2. `[Галерея начинок]` — карточки: фото, название, краткое описание, цена за кг. `API: GET /custom-cakes` → `fillings[]`.
3. `[Этапы работы над заказом]` — пронумерованный список шагов (например: «Консультация → Согласование дизайна и вкуса → Изготовление → Получение») — контент из `PageContent[custom_cakes]`.
4. `[Примеры авторских тортов]` — карточки из `custom_cakes[]` (фото, название, цена «от»).
5. `[Форма заявки на консультацию]` — поля: имя\*, телефон\*, 🆕² повод (select), дата события (date-picker, не в прошлом), число гостей, описание пожеланий, загрузка фото-референса (опционально), чекбокс согласия на обработку ПД\* (обязателен). Отправляется как `multipart/form-data`. `API: POST /custom-cakes/consultation`.

🆕² Этапы работы (п. 3) — **четыре шага с обозначенными точками связи**: заявка → согласование эскиза, начинки, веса и цены с Еленой → предоплата и фиксация даты → получение. Это лечит главный провал пути Ани — тишину после предоплаты («про меня не забыли?»). Тексты этапов — `PageContent[custom_cakes].content.stages[]`.
6. `[Footer]`.

**Desktop:** галерея начинок и примеры тортов — сетка 3 колонки вместо горизонтального скролла/вертикального стека, форма консультации может стоять в две колонки (поля слева, поясняющий текст/фото справа).

**Состояния формы:** успешная отправка → инлайн-подтверждение «Заявка отправлена, свяжемся в ближайшее время» без перехода на отдельную страницу (сохраняет паттерн из старого кода для этой конкретной формы); ошибка валидации — подсветка конкретных полей (React Hook Form + Zod).

## 7. Контакты (`/contacts`)

**Mobile:**

1. `[Header]`, `[Заголовок страницы]`.
2. `[Контактные данные]` — адрес, телефон (кликабельный `tel:`), часы работы (будни/выходные отдельно, как в старом коде), часы доставки. `API: GET /pages/contacts`.
3. `[Виджет карты]` — Яндекс.Карты/Google Maps, встраиваемый iframe/SDK по `map_embed_code` из контента страницы (обязательно к согласованию, раздел 6 договора).
4. `[Форма обратной связи]` — имя, телефон, сообщение, чекбокс согласия на ПД. `API: POST /contacts/feedback` (см. примечание ниже).
5. `[Ссылки на соцсети]`.
6. `[Footer]`.

**Примечание по форме обратной связи:** в старом Django-коде на странице контактов фактически переиспользовалась та же `ConsultationForm`, что и для тортов на заказ (см. `views.py: contacts`). В новом API решение зафиксировано: обе формы пишут в одну таблицу `ConsultationRequest` (не заводим вторую сущность ради визуально идентичной формы), но через два разных эндпоинта — `POST /custom-cakes/consultation` и `POST /contacts/feedback` (см. `02-api-contract.md`) — каждый проставляет своё значение поля `source` (`custom_cake` / `contact_page`, см. `01-data-model.md`, раздел ConsultationRequest). Так заявки не теряются, разграничиваются в админке по источнику, а роутинг и rate-limit у двух форм настраиваются независимо.

**Desktop:** карта и контактные данные — рядом (карта справа/слева), форма — под ними или сбоку, в зависимости от макета дизайнера.

## 9. Оформление заказа (`/checkout`)

**Mobile:**

1. `[Header]`, хлебная крошка «Каталог → Корзина → Оформление заказа» (как в старом коде).
2. `[Форма контактных данных]` — имя\*, телефон\*.
3. `[Способ получения]` — радио-переключатель «Самовывоз / Доставка». При выборе «Доставка» — 🆕 разворачивается поле «Адрес доставки»\* (обязательное условно — отсутствовало в старом коде, см. `ANALYSIS.md`, таблица сравнения полей `Order`).
4. `[Желаемая дата]` — 🆕 date-picker (отсутствовал в старом коде). 🆕² Минимальная дата — `earliest_date` из `GET /cart` (сегодня + наибольший срок изготовления); если в корзине есть позиция под заказ, дата обязательна. Рядом — 🆕² `[Интервал]`: 09–12 / 12–15 / 15–18 / 18–21 (`delivery_interval`).
5. `[Комментарий к заказу]` — необязательное текстовое поле.
6. `[Согласие на обработку ПД]` — обязательный чекбокс (в старом коде был во вёрстке, но не сохранялся на бэкенде — здесь обязателен и на фронте, и в модели `Order.consent_pd`).
7. `[Сводка заказа]` — состав корзины (превью), итоговая сумма — на мобильном это блок **над** кнопкой отправки, чтобы пользователь видел, что подтверждает.
8. `[Кнопка «Подтвердить заказ»]`.
9. `[Footer]`.

**Desktop:** двухколоночная раскладка — форма слева, липкая сводка заказа справа (как было в старом коде, эта раскладка признана удачной).

**После отправки:** редирект на `/order/[order_number]` — страница подтверждения (см. служебные страницы), плюс письмо-уведомление администратору (см. `05-nonfunctional-and-acceptance.md`).

## Служебные страницы

### Страница подтверждения заказа (`/order/[order_number]`)

Блоки: иконка успеха, текст «Заказ №{order_number} принят», краткая сводка (что заказано, сумма, способ получения, дата), текст «Мы свяжемся с вами по телефону {phone} для подтверждения», CTA «Вернуться в каталог».

### 404 (`not-found.tsx`)

🆕 Отсутствовала в старом проекте. Блоки: иллюстрация/иконка, текст «Страница не найдена», CTA «На главную» и «Перейти в каталог».

### Политика конфиденциальности (`/privacy`)

Переносится как юридический текст (уже есть готовый текст в старом проекте, `privacy_policy.html`, оператор — ИП Мельниченко Е.А.) — статичная страница с текстом, без интерактивных блоков, только `[Header]` + текст + `[Footer]`.

### Согласие на обработку персональных данных (`/consent`) 🆕²

Служебная страница из карты сайта (PDF «Этап 1», раздел 11). Статичный юридический текст согласия, на который ведёт ссылка у чекбокса согласия во всех трёх формах (заказ, заявка на торт, обратная связь). Версия текста совпадает с `PRIVACY_POLICY_VERSION` в `apps/api/app/services/orders.py` — при изменении текста версию нужно поднять, чтобы в заявках было видно, с какой редакцией человек согласился.

### Пользовательское соглашение (`/terms`)

🆕 Отсутствовала в старом проекте, обязательна по разделу 3 договора. Текст согласовывается с заказчиком/юристом отдельно — на этапе разработки Claude Code создаёт страницу с типовой структурой (предмет соглашения, права/обязанности сторон, порядок использования сайта, ограничение ответственности), финальный текст — не инженерная задача, а юридический контент, который передаёт заказчик.

## Общие блоки, повторяющиеся на всех страницах

### Header

Mobile: компактное лого слева, бургер-меню и иконка корзины (с бейджем количества товаров) справа, шапка липкая (sticky) при скролле. Desktop: лого + горизонтальное меню (Каталог / Торты на заказ / О нас / Примеры работ / Контакты) + акцентная кнопка заказа + иконка корзины.

🆕² По карте сайта из PDF «Этап 1»: порядок меню — **Каталог (с выпадающим списком 5 групп) · Торты на заказ · Примеры работ · О нас · Контакты**; справа — поиск, корзина, телефон с часами работы и кнопка «Заказать торт». В шапке — рейтинг Яндекса (`yandex_rating`, `yandex_reviews_count`, ссылка `yandex_maps_url` из `GET /pages/contacts`). Главное действие сайта — «В корзину» и «Оформить заказ», второе — «Заказать торт»; телефон и Telegram доступны всегда, но кнопкой первого уровня не становятся.

### Мобильное меню (шторка/модалка)

Открывается по бургеру: ссылки на все разделы + акцентная кнопка заказа, крестик закрытия.

### Footer

Телефон (кликабельный), часы работы, навигационные ссылки (О нас, Каталог, Политика конфиденциальности, Пользовательское соглашение), ссылки на соцсети, копирайт + дисклеймер «сайт не является публичной офертой».

### Floating-виджет соцсетей

Плавающая кнопка в правом нижнем углу, при клике раскрывает 1–2 иконки соцсетей (в старом коде — VK, Telegram отключён комментарием). Финальный список соцсетей уточняется у заказчика.

### Индикатор корзины

Счётчик товаров в иконке корзины в шапке — обновляется реактивно (React Query invalidate/refetch после любой мутации корзины), без ручной синхронизации через `localStorage`, как это было в старом коде.
